# Critical Prompt 09 検証結果：物理応用・型・単位

## 対象補正

元プロンプトは「第8章 物理応用」としているが、現行原稿の第8章は物理応用章ではなく、`d,*` 記法と `∇` 記法の翻訳辞書を完成させる章である。

現行原稿で物理応用が主に出る箇所は次の通り。

- 第3章：仕事、流量、密度、質量
- 第6章：電場・電流密度の例、ヘリシティ
- 第9章：点電荷の電場
- 第10章：マクスウェル方程式
- 第12章：リーマン-ジルバーシュタインベクトル、ディラック演算子

したがって Prompt 09 は、そのまま第8章だけに実行すると不適切である。今回は「第8章に物理応用監査をかける妥当性」と、第8章が後続の物理章へ与える型の影響を確認する。

## 第8章の実内容

第8章の主対象は、次の翻訳表である。

| ベクトル解析 | 第8章の `d,*` 表記 | 厳密な標準対応 |
|---|---|---|
| $\nabla f$ | $df$ | $(df)^\sharp$ |
| $\nabla\times F$ | $\ast d\omega$ | $(\ast dF^\flat)^\sharp$ |
| $\nabla\cdot F$ | $\ast d\ast\omega$ | $\ast d\ast F^\flat$ |

また、円柱座標で `*` の辞書が計量に応じて変わることを説明し、発散・回転の標準公式を導いている。これは物理応用というより、曲線座標と型変換の橋渡しである。

## 問題候補

### 1. Prompt 09 は章指定が現行原稿と合っていない

該当箇所：

- `nabla_kaitai_critical_prompts.md:300`
- `nabla_kaitai_critical_prompts.md:305`

第8章だけを対象に「力・仕事・電磁気・流体・電荷密度・電流密度」をすべて監査するのは不可能である。現行章構成では、物理応用監査は第3章・第6章・第9章・第10章・第12章へ分散して実行すべきである。

Issue 化判定：GitHub Issue ではなく、実行計画上の補正として扱う。

### 2. 第8章の翻訳表は `♭/♯` を明示していない

該当箇所：

- `manuscript/ja/ch08/ch08.md:108-114`
- `manuscript/ja/ch08/ch08.md:118-126`
- `manuscript/ja/ch08/ch08.md:130-144`

第8章は `∇f` と `df` を「縦と横」「転置の関係」として説明している。これは直交デカルト座標では数値的に正しいが、標準理論では計量同型が必要である。

修正方針：

- 第8章の辞書表に「ベクトル解析の矢印に戻すには、直交デカルト計量による同一視を使っている」と注記する。
- `grad` と `rot` については `sharp` 相当の操作を明示する。

Issue 化判定：採用候補。Prompt 07/08 の `grad/rot/div 型整理` Issue に統合する。

### 3. 第8章の参照番号が旧構成のまま

該当箇所：

- `manuscript/ja/ch08/ch08.md:102`
- `manuscript/ja/ch08/ch08.md:126`
- `manuscript/ja/ch08/ch08.md:146`
- `manuscript/ja/ch08/ch08.md:292`

`第6章 §5.5`, `第7章 §6.7`, `第6章 §5.1.3` など、章番号と節番号が混線している。内容理解に直接影響するため、既存の参照ずれ一括 Issue に含める。

Issue 化判定：採用候補。ただし一括参照修正に統合。

### 4. 円柱座標の発散・回転公式は、成分の種類を明示している点がよい

該当箇所：

- `manuscript/ja/ch08/ch08.md:322`
- `manuscript/ja/ch08/ch08.md:324-330`
- `manuscript/ja/ch08/ch08.md:356-364`

第8章は、ベクトル解析の正規直交成分 $F_\theta$ と form 係数 $rF_\theta$ の違いを明示している。これは非常に重要で、曲線座標での単位・次元の破綻を避ける説明になっている。ここは Issue 化しない。

## 今回の結論

Prompt 09 は「重要だが章指定が不適切」。第8章を物理応用章として Issue 化するのではなく、次の補正で実行する。

1. 第8章については翻訳辞書・曲線座標の型監査として扱う。

3. 第8章の旧章番号参照と `♭/♯` 不明示は既存候補に統合する。
